Frequently Asked Questions

Does VeloOverlay work offline?

Yes, 100%. Video and data parsing, syncing, and rendering all happen natively on your machine to ensure your files stay private.

What data formats are supported?

We natively parse .FIT, .GPX, and .TCX tracking files from Garmin, Wahoo, action cameras, and Strava. Renders can additionally emit a .CSV telemetry sidecar for downstream tooling.

Can I extract transparent overlays?

Yes, you can choose to render the overlay graphics over a transparent background (Apple ProRes 4444) to drop into Premiere Pro or Resolve.

Do I need a high-end GPU?

A dedicated GPU helps rendering speeds considerably (using NVENC or VideoToolbox), but the software falls back securely to CPU processing if required.

Does Flyover Map require an API key?

No. Map vector tiles are retrieved dynamically and cached for free usage up to reasonable limits, requiring zero setup from your side.

Can I apply a color grade or LUT to my video?

Yes. Drop your .cube LUT files into a library folder (configured in Settings → Paths), then select a LUT in the Video Effects panel before rendering. The grade is applied inside the FFmpeg encode pass with no quality loss.

Can I pull rides directly from Strava?

Yes. Connect your Strava account in Settings → Integrations and import any activity. GPS, heart-rate, power, cadence and temperature streams are converted to TCX locally and dropped into the editor — no manual file export required.

Can I drive renders from Claude or other AI assistants?

Yes. VeloOverlay ships an MCP server that exposes render, preview, and project-inspection tools. Point a compatible client (Claude Desktop, Cursor, JetBrains AI) at the server to spin up overlay variants and batch renders from chat.
